# 任务工作台：实时监控、轨迹回看和文字交付

## 使用

在 Studio 的“实时监控”查看正在运行的任务；在“本机轨迹”点开运行，使用同一工作台回看。

- 左侧是计划子任务，下面的行是实际决策动作。一个子任务可以对应多个动作；框架等待和报告生成不增加决策次数。
- 右侧顶部用上一/下一动作、动作下拉框或键盘左右键切换。回看旧动作后不再自动跟随；点击“回到最新动作”恢复。
- 选择历史动作时，左侧显示该动作记录的队列状态与计划版本。重规划保留已经核查完成的子任务 ID；旧动作仍属于原来的计划。可以切换计划版本检查差异。
- 截图分为“动作前”“动作后”“实时画面”。前两者是动作证据，后者是受控浏览器每秒左右一次的只读预览，不参与验收。不截断或拉伸图片，可放大查看。桌面任务使用动作快照，不伪装成连续浏览器预览。
- “模型输入”包含实际发送的完整 messages、模板元数据、AX/DOM 和图片；“模型输出”包含原始响应、解析动作及定位/执行通道。
- “执行与核查”区分代码检查、Jev 的模式选择、动作后联合核查、子任务核查和整项验收。一次请求有几道问题就展示几个答案，不把四问误算成四次 HTTP 请求。派发成功与核查通过分别显示。
- “任务结果”显示最终文字、来源、核查状态，可保存 Markdown。文字来自真实模型流式接口，不是把已经完成的答案拆字播放。开始输出时尚未验收，状态会明确标示。

## 实现边界

### 证据和进度

`StepState` 保存已观察网页的来源与正文片段。只采集浏览器实际观察内容，不另行抓取未知网页，也不把决策模型的记忆当作网页事实。最多保存 24 个来源，每个来源有长度边界；模型上下文另外限长。引用必须使用已记录的来源编号，空答案、截断和传输异常不能成为成功交付。

多页采集进展需要“新的正文证据”和独立核查的进展判断同时成立，不能仅用不断切换网址清除卡死计数。重复相同正文不会获得新进展。所有任务仍受总时间与决策步数限制。

报告由单独的 reporter 调用生成，记录原始请求、响应、首段延迟和 token 用量；它不冒充新的 GUI 动作，也不标为决策策略的训练样本。报告生成后仍走所选核查器。使用 Jev 时，整项核查还逐项检查文字交付要求，避免“比较单位费用”替代“比较总费用”等遗漏。明确遗漏可以触发一次文字修订，不需要点击浏览器；不确定或代码失败不能被修订流程改写成成功。

已完成的子任务表示当时有完成证据，不意味着其条件永远不变。最终确定性条件照常复查。历史记录没有保存动作与计划的对应关系时显示未记录，不根据动作顺序猜测。

### 运行事件与恢复

新增 `action_context`、`plan_revision`、`report_start/delta/complete/error/verification` 等事件。动作开始时固定记录计划 ID，防止核查后队列推进使动作归属错位。

实时接口另存当前运行的可重建状态，不受原有 200 条调试日志上限限制。HTTP 轮询按序号增量返回；实时预览只保留最新一帧；报告增量附累计正文，能从漏掉的更新恢复。断线不会因为漏掉一段文本而永久缺字。完整事件日志仍独立落盘。

未导出 trajectory.json 的中断运行也能从已落盘 JSONL 重建动作和部分报告，保留“运行记录尚未结束”的状态。历史回看读取内容寻址图片，不把不存在的动作后截图替换为动作前截图。

本机轨迹列表与详情使用同一运行统计，包括已有启动器记录的进程总用时。没有上报的 token 不做估算。Jev 分数仍是未校准模型分数，不是成功概率。

### 文件位置

- `viz/static/workbench.js`、`workbench.css`：统一渲染、导航、折叠动画、截图和文字结果。
- `viz/workbench.py`：完整/中断轨迹的公共数据投影。
- `report_delivery.py`：来源、流式报告、引用检查和修订上下文。
- `browser_session.py`：不改 AX 引用、不聚焦窗口的任务浏览器预览。
- `tests/test_workbench_delivery.py`、`test_workbench_browser_live.py`：报告、事件恢复、预览与前端交互回归。
- `experiments/workbench_live_suite.py`：真实模型的多页面分析/原生下载验证入口。

## 运行验证

单元和集成回归：

```bash
python -m pytest -q tests/test_workbench_delivery.py tests/test_step_progress.py
python -m pytest -q tests/test_workbench_browser_live.py --run-browser-integration
```

真实模型验证会调用 Qwen 和 Jev，需要本机已配置凭据和可访问端点：

```bash
python experiments/workbench_live_suite.py
```

该套件使用专用无头 Chromium 和本地可核对答案的测试网站；决策、核查均是真实远端模型。不是互联网网站覆盖率评测，也不验证原生桌面操作。它可以在 Linux 上运行浏览器集成测试，原有 Studio 本机原生环境启动器的平台限制没有因此改变。可通过 `WORKBENCH_DECISION_MODEL`、`WORKBENCH_DECISION_URL`、`WORKBENCH_JEV_URL` 覆盖端点。

自动化 pytest 的运行日志写入各测试的临时目录，不进入 Studio 历史。单独使用 `experiments/live_browser_case.py` 的简单检查默认写入项目上层 `.runtime/smoke-tests/`；只有显式传入 `--record-history` 才发布到历史列表。多步骤场景套件已显式启用该参数，成功和失败都保留。正常用户任务的记录规则不变，不按步数或成功与否隐藏真实任务。

完整回归的既有失败、各轮真实运行结果和本轮截图见同目录的 `workbench-validation.md`。不能把一次运行成功解释成任意网站、任意模型配置均已稳定。
