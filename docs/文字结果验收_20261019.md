# 文字结果验收：网站功能介绍与信息搜集

## 对应问题

任务如“去 w3 网站看一下在 3MS 可以做什么事情”，用户需要的是有来源的功能说明。浏览器当前截图不是文字交付物；首页动态内容改变也不代表已经核查过的文字失效。

旧路径存在两项不足：此类口语任务没有被 `wants_report` 识别；整任务模型验收后的复核依赖当前页面截图指纹。此外，运行端支持最高概率标签选择，接近的选项可能在两次请求中翻转。

本次修改依据 Windows 运行分析及当前源码完成，未访问华为内网，也没有重放那次 Windows 原始轨迹。

## 新流程

1. 把“可以做什么”“网站用途/功能”等识别为文字交付任务。
2. 从实际网页观察收集来源，框架流式生成正文，并保存正文、来源编号、网址和观察文本。来源不能由模型自行编造。
3. 对纯信息介绍任务，用 Jev 核对原问题、正文与来源文本，一次 HTTP 请求包含整项内容核查与逐项要求核查。截图不作为必需输入；不要求把答案写进网页或下载为文件。
4. 代码仅验证交付物存在、引用编号对应已观察来源和输入容量，不能凭这些条件直接判成功。真实性、覆盖范围仍由独立语义核查判断。
5. 若文字验收采用最高概率策略，最高概率低于 0.5 或第一、第二名分差低于配置的 `margin`，该次判断保留 `unknown`。原始概率继续记录，不作为真实成功率。
6. Jev 明确 `failed` 时，不寻找另一个模型将其覆盖；根据失败覆盖项最多修订正文一次。Jev `unknown` 时，复用决策模型配置的独立核查实例，基于同一文字证据补审一次，不共享操作员对话，不增加浏览器动作。未配置可用模型时仍为未知。
7. 语义核查通过后，最终复核比较原问题、正文及来源快照的内容指纹。仅页面动画/轮播变化不会触发新视觉判定；正文或来源真的改变则必须重新核查。
8. 补审仍不确定时，保留正文及来源，结果为 `completion_inconclusive`，前端显示证据不足，停止对同一份内容重复点击或评审。

## 边界

- 不把“非空答案＋任务关键词＋引用”当作语义正确的充分条件。
- 不要求用户仅查询“网站能做什么”时逐一实际执行那些功能。
- 下载、写文件、提交审批等混合任务仍保留原有文件、系统、界面验证；明确的代码失败不能被文字审查覆盖。
- 显式指定的最终 URL 等契约仍重新采集证据检查。
- 来源过长时，保留完整正文，按任务和正文相关性选取原始来源行，并标记截断。不能据裁剪后的缺失推断整个网站不存在内容。超容量时明确保留不确定。
- 语义通过继续标记为模型核查，不升级成确定性评测成功或有效 RL 奖励。

## 前端与轨迹

新增用途标签：

- `report_review`：Jev · 文字结果与来源核查。
- `report_review_fallback`：模型 · 独立文字语义复核。

保留两次调用各自的输入、输出、概率、耗时及原 Jev 判断。`final_review_reused` 事件记录复用原因与证据指纹。

## 验证

自动化覆盖口语任务识别、无截图文字审查、选项近似打平、一次独立补审、明确失败不可被补审覆盖、动态截图变化、正文/来源变动撤销通过、最终 URL 条件仍须满足、未知停止及前端用途/耗时展示。测试使用隔离的模拟环境和服务响应，不写入用户历史任务列表。

另直接调用 51 服务器的 `d3-flash`，用显式构造的示例平台来源进行两次文本请求：有来源支持的功能说明为 `passed`（约 165 ms），编造股票交易/报销审批/订票功能为 `failed`（约 137 ms）。这是两个简单接口案例，不代表 Windows 内网任务成功率或通用延迟承诺。Windows 的实际 3MS 任务需更新后复测。
