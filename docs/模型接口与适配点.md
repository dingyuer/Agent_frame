# 模型接口与适配点（决策 / Jev / Grounding）

> 用途：专家新版本合并进来后，按本文档把模型调用适配到我们的运行环境。
> 三类模型**全部通过配置注入**（YAML / CLI / .env），代码里只有默认值，没有硬编码业务端点。

## 一、决策模型（decision model）

| 项 | 位置 |
| --- | --- |
| 客户端类 | `model/decision_model.py` → `ChatModel(cfg: ModelConfig)` |
| 配置 dataclass | `config/__init__.py` → `ModelConfig`（name/url/api_key/temperature/max_tokens/timeout/vision/disable_thinking/capture_rollout/四个 revision） |
| 别名注册表 | `model/decision_model.py` → `MODEL_REGISTRY`（"9b"/"27b" 别名 → 真实模型名） |
| 工厂 | `build_decision_model(cfg)` → `ChatModel` |

**协议**：OpenAI 兼容 `POST {url}/chat/completions`（openai SDK）。

适配时必须保留的请求特征（框架依赖）：
- **视觉**：`build_vision_message()` 把截图编为 base64 data URL 塞进 `image_url` 多部分消息；`encode_image()` 是全局共用编码器。
- **关思考**：`disable_thinking=True` 时发 `extra_body={"chat_template_kwargs": {"enable_thinking": False}}`（vLLM/Qwen 约定）；服务端不认识 `extra_body` 时自动降级重试。
- **JSON 约束**：`json_mode=True` 发 `response_format={"type": "json_object"}`；不支持时降级。
- **RL 采集**：`capture_rollout=True` 时请求 `logprobs` + `return_token_ids`，并接受网关扩展 `rollout_metadata`（见 `_capture_rollout`）；版本校验失败标 `rl_ready=false`。
- **轨迹元数据**：每次调用后 `model.last_call` 存 messages/generation/response/usage/latency，pipeline 依赖它落轨迹。

**代理行为**：`httpx.Client(trust_env=False)` —— 内网端点直连、绕开系统代理。**专家环境若需要代理才能出网，这里是第一个要改的点。**

**当前部署**：Qwen3.6-27B @ `http://7.246.80.237:48888/v1`，api_key=EMPTY。

构造入口（合并时检查这几处的参数名是否对齐）：
- `main.py`：`Config.load(config.yaml)` → `build_decision_model(cfg.model)`
- `run_windows_local.py:452`：`--model/--model-url/--model-api-key/--temperature`
- `viz/runner.py:87`：OSWorld VMware 批跑
- 独立**核查模型**（verifier）：`run_windows_local.py:458`，`--verifier-model/--verifier-url`，同样是 `ChatModel`（temp 0、max_tokens 768），assist 模式下 Jev unknown 时回退到它。

## 二、Jev 决策核查（Decision 3.0）

| 项 | 位置 |
| --- | --- |
| 客户端类 | `model/decision_judge.py` → `DecisionJudge(config: DecisionJudgeConfig)` |
| 配置 | 同文件 `DecisionJudgeConfig`（url/model/revision/timeout/threshold/margin/api_key/review_mode/recheck_unknown） |
| 装配点 | `pipeline.py:132-133`：`DecisionJudgeConfig(**decision_judge_dict)`，**url 为空则不启用** |
| CLI 参数 | 同文件 `add_judge_arguments` / `judge_config_from_args`（`--judge-url/--judge-model/--judge-threshold/--judge-margin/--judge-timeout/--judge-review-mode/--judge-no-recheck`） |
| Studio 链路 | 前端 `viz/static/index.html:1899 decisionJudgeConfig()` → 后端 `viz/server.py:858 _judge_cli_args()` → 子进程 CLI |

**协议**：**不是** chat completions，是 System One 类型化接口（vllm-sr/d3 协议）：

```
POST {url}   # 自动补全为 .../v1/systemone
请求: {"model": str, "state": str|json, "questions": {qid: {type: choice|noul|score, criteria, instructions}}, "images": [data_url]}
响应: {"model": str, "answers": {qid: {"type":"choice","choice":label,"probabilities":{label: p}, "confidence": entropy}}, "usage": {...}}
```

框架依赖的响应不变量（`_choose`/`_answer` 强制校验）：
- choice 的 `probabilities` 键集合必须等于请求的 criteria 键集合，概率和 = 1（±0.001）；
- `choice` 必须是最大概率项；`confidence` ∈ [0,1]；
- score 类型必须满足 `score == Σ k·p_k` 且 `legend` 与请求等级一致。

**采纳规则**（`decision_judge.py:154`）：`P(top) ≥ threshold 且 P(top) − P(次优) ≥ margin`，否则塌缩为 `unknown`。
threshold ∈ [0.5, 1]、margin ∈ [0, 1]（config 校验）。review_mode：`assist`（unknown 回退独立核查模型）/ `exclusive`（Jev 独立裁决）。

pipeline 用到的方法：`classify_task`（任务环境分类）、`readiness`（加载轮询）、`download_wait`、`select_opened_tab`、`assess_transition`（动作后诊断）、`review`（步骤/整体验收）。

**密钥**：`DecisionJudgeConfig.api_key` 或环境变量 `DECISION_JUDGE_API_KEY`。
**当前部署**：d3-flash 9B @ `http://10.44.101.62:8007/v1/systemone`，threshold 0.9 / margin 0.15。
另有一套对比实验走 `.env` 的 `JEV_*`/`VLM_*`（`experiments/jev_vs_vlm.py`、`viz/jev_demo.py`），与运行链路独立。

## 三、Grounding 视觉定位

| 项 | 位置 |
| --- | --- |
| 抽象接口 | `model/grounding.py` → `Grounding` ABC：`locate(screenshot, target: str) -> GroundingResult(x, y, confidence)` |
| 注册表/工厂 | 同文件 `GROUNDING_REGISTRY` / `build_grounding_model(cfg: GroundingConfig)` |
| 配置 | `config/__init__.py` → `GroundingConfig`（name/url/api_key/width/height/timeout） |

三个实现（**协议不同**，适配时按专家部署选对类型）：

| 类型 | 实现 | 提示词 | 坐标空间 |
| --- | --- | --- | --- |
| `ui-tars` | `adapters/uitars_grounding.py` `RealUItarsGrounding` | `Query:{target}\nOutput only the coordinate...` | **绝对像素**，默认等于截图尺寸；端点若缩放需显式传 `grounding_width/height` |
| `ui-venus2` | `adapters/uivenus2_grounding.py` `UIVenus2Grounding` | `Output the center point ... [x,y]`，关 thinking | **[0,1000] 归一化**，支持 `[x1,y1,x2,y2]` 取中心、`[-1,-1]` 拒答 |
| `qwen-plus` | `adapters/qwen_grounding.py` `QwenPlusGrounding` | 12×9 网格两段式（粗定位→裁剪放大细定位） | 网格行列 → 像素 |

共同约定：
- 全部 OpenAI 兼容端点 + `trust_env=False`；
- 失败返回 `GroundingResult(-1, -1, confidence=0)`，`resolve_coords()` 把它转成 `None` 让执行器拒绝（**不允许兜底成屏幕中心**，NullGrounding 仅供离线测试）；
- `pipeline._resolve()` 每步把 `grounding.width/height` 动态设为**实际截图尺寸**，所以截图分辨率变化不用改配置；
- 包装层：`model/grounding.py` 里的 `UItarsGrounding`/`UIVenus2Grounding` 懒委托到 adapters 的真实实现。

**当前部署**：UI-Venus-2-9B @ `http://7.246.80.189:8001/v1`。

构造入口：`run_windows_local.py:461-465`（`--ground-type ui-tars/ui-venus2/qwen-plus`）、`viz/runner.py:91-104`、`viz/server.py:754-776/903-920`（Studio 透传 CLI）。
Studio 下拉选项来自 `config/model_presets.yaml`（`decision_models` / `grounding_models`，其中 `type` 字段决定 grounding 协议）。

## 四、合并专家版本时的适配清单

1. **端点/密钥**：只动配置层（`config.yaml`、`.env`、`config/model_presets.yaml`、CLI 参数），不改代码。
2. **代理**：三处客户端全部 `trust_env=False`。专家环境若必须走代理，改 `decision_model.py:_get_client`、`decision_judge.py:__init__`、两个 grounding adapter 的 `_get_client`（共 4 处），或加配置开关。
3. **决策模型能力**：必须支持视觉 `image_url`；最好支持 `response_format=json_object` 和 `chat_template_kwargs.enable_thinking`（不支持会自动降级，只是慢/格式漂移多）；RL 采集另需 `return_token_ids`+`logprobs` 或 `rollout_metadata` 网关扩展。
4. **Jev**：必须实现 System One 类型化协议（state+questions+images → 带 probabilities 的 answers）；没有 Jev 服务时 `--judge-url` 留空即可整链关闭，验收回退 code + 独立核查模型。
5. **Grounding 坐标空间**：确认专家部署的模型输出是绝对像素还是归一化坐标，选对应 `--ground-type`；UI-TARS 端点若内部缩放图像，构造时传 `grounding_width/height`。
6. **模型名透传**：CLI/前端的 `name` 原样发给服务端（`resolve_model_name` 只映射已知别名），端点侧以实际加载权重为准。
